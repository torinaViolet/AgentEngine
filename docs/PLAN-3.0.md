记录日期：2026-10-08。

## 1. 确定的模块边界

| 模块 | 负责的事情 |
| --- | --- |
| Message | 独立消息身份、角色、内容块和元数据，自身内容的读取与编辑 |
| Session | 消息组织、结构位置、选择状态、查询、执行关联、会话导入导出 |
| PromptBuilder | 临时请求上下文构建、来源追踪和不消费注入寿命的预览 |
| Provider | 平台协议、请求参数转换、HTTP/SSE 和统一响应解析 |
| Generator | 一次模型生成，统一请求构建与配置，关联本次生成事件和结果 |
| Tool / ToolExecutor | 平台无关工具定义、参数校验、执行授权、人工审批和工具执行 |
| Agent / Run | 持续上下文、多步骤任务编排、工具循环、运行控制与会话提交 |

三种会话为 TreeSession、ListSession 和 AgentSession。所有会话保留交互、模型步骤与工具执行记录；ListSession 默认候选单位为 sequence，另支持 turn。

Generator 作为独立的小单元，不自动执行工具或维护会话。Agent 组合上述能力，运行多步自主流程。Provider 与 Generator 的代码应有实际分工：平台协议实现与单次生成的配置、身份、标准事件和结果管理分别归属，避免复制协议解析或形成仅转发调用的重复公共层。

## 2. 实施采用的默认选择

### 2.1 消息编辑与身份

- Message 采用 class，保留 setText / setParts 等内容编辑能力，补齐追加、思考及内容块编辑。
- 内容、标签和元数据经受控方法更新；公开视图不可绕过方法直接修改内部数据。
- 稳定 ID 与内容版本独立；内容编辑不改变消息身份。
- Message 提供轻量变更通知；Session 监听注册消息的变更，维护索引、历史失效信息和提交冲突检测。
- 克隆默认创建新身份；构建请求使用带来源的值快照，不修改会话对象。
- 内容编辑不包含父子节点操作或模型请求行为。

### 2.2 会话、轮次和查询

- 公共会话契约暂使用 SessionLike，AgentSession 留给按交互轮组织的具体类。
- 查询默认 scope 为 active，显式 all 才查询其他分支或候选；提供标识、角色、内容、标签、元数据和执行归属查询。
- 消息身份与结构位置身份分别管理。结构编辑必须能明确目标节点、候选或交互轮。
- 轮次与执行记录由 Session 保存，公共记录区供三种会话复用，避免三套独立的追踪实现。
- 同一次交互的重生成、继续和恢复关联原 Turn，并保留独立的 Run 与 Step。
- 手动消息可以显式关联轮次；来源不完整时保留未知，不伪造模型调用和工具执行。
- 不默认保存全部原始请求、响应或重复媒体；保存必要的执行事实与生成贡献关联。
- 序列化带类型和版本，保留组织关系、当前选择及执行记录，并按深历史场景设计。

### 2.3 配置、传输与扩展

- 使用有类型的对象配置，区分生成参数、运行控制、工具策略和上下文构建。
- 常用配置有一个明确主入口；单次调用只覆盖所属配置，平台专属参数在 Provider 入口处理。
- 公开查看最终生效配置的能力，不依赖用户记忆合并顺序。
- Provider 支持自定义地址、传输和媒体解析；默认传输使用标准 Web 能力，Node 文件能力保留显式子入口。
- 首先实现 OpenAI-compatible、Anthropic 与 Gemini；现有 OpenAI Responses 能力列入独立协议实现与验证，不混作 Chat Completions。
- 不支持或冲突的统一配置给出明确错误；HTTP 错误提供 status。具体模型能力由服务端确认，平台专属参数可扩展。
- 数据库、网络代理部署、应用凭据存储、角色宏和世界书规则由业务通过扩展入口实现。

### 2.4 生成、工具执行与 Agent

- Generator.generate 表示一次模型调用，允许返回工具调用，流式与完整响应有一致结果语义。
- Agent.chat 开始用户交互；Agent 的既有上下文执行入口暂定 run；continue 扩展已有回复；resume 恢复可继续的执行。
- Agent.generate 不作为新的公共单次生成入口，避免与 Generator.generate 混淆；2.x 迁移方案单独说明。
- 传入 Session 时使用该实例；不传入时必须提供 mode。PromptBuilder 未提供时创建默认实例，两者始终可获取。
- 工具执行模块区分模型可见性、启用和每次执行授权，并保留运行中的动态工具定义。
- 工具参数以平台无关 JSON Schema 表达，接收已有 schema，执行前校验；具体校验实现和依赖在该模块实施时选择。
- 参数失败、工具异常、执行顺序与并发策略分别定义，错误选项不隐式决定并发方式。
- 每个模型步骤有稳定身份，工具执行有自己的内部标识；流式事件与会话结果可以准确关联。
- 当前 maxTurns 的模型调用限制改用 maxSteps 等明确语义，默认模型步骤上限沿用 10；其余预算按配置决定。
- 同一 Agent 默认只运行一个活动任务，多个 Agent 或独立 Generator 可由业务调度。

### 2.5 提交、继续与恢复

- 模型输出完成、会话内存提交与业务持久化成功是不同阶段。
- 请求前、模型步骤提交前后、运行结束有明确生命周期；普通通知事件不承担需要等待的执行转换。
- 开始生成时绑定目标及版本；发生目标编辑或删除冲突时保留未应用结果，返回明确冲突信息，不默默覆盖。
- continue 默认在原交互内提交，将文本与思考追加到目标，并记录新增生成贡献。
- 临时继续指令及思考回传属于请求上下文，不需要先写入 Session 再删除。
- continue 中的工具调用与结果保持协议关联；不将完整工具轨迹压成一条文本。
- 完成、中止和失败采用明确保留规则，先以 CharacterEditor 已有续写场景验证，再确定公开策略参数。
- 会话导入可以恢复内容与执行记录；恢复进程内运行和跨进程恢复执行分别设计，不把重新导入会话视为自动恢复工具现场。

## 3. 实施阶段与完成标准

| 阶段 | 主要成果 | 完成标准 |
| --- | --- | --- |
| 1. 基础数据 | Message、内容块、身份、版本、通用执行记录类型 | 内容编辑保留未涉及的块；变更可感知；序列化不包含节点或运行时对象 |
| 2. 会话模型 | SessionLike、TreeSession、ListSession、AgentSession、查询与导入导出 | 三类会话历史正确；候选、分支和轮次关联可恢复；编辑和删除保持结构一致 |
| 3. 平台与生成 | 可注入传输、协议转换、Provider、Generator | 三家协议及 Responses 的 fake 响应可解析；流式与非流式一致；单次生成不执行工具或修改会话 |
| 4. 工具执行 | 平台无关定义、校验、授权、审批、动态工具 | 独立执行入口具备同样审批能力；取消和超时释放等待；新增工具可供后续步骤使用 |
| 5. Agent 编排 | chat、run、continue、resume、提交与运行事件 | 多步骤工具循环和停止条件正确；续写保存贡献；冲突不覆盖用户编辑；partial 与已完成步骤可区分 |
| 6. 上下文扩展 | PromptBuilder、来源信息、预览和异步扩展 | 临时构建不改变会话；预览不消费状态；提交和结算生命周期满足业务接入 |
| 7. 集成与迁移 | 六组业务样例、2.x 迁移说明、浏览器与导出检查 | 样例可用；包根无 Node builtin；既有业务所需能力有清楚替代接口 |

阶段间可以按依赖调整内部实现顺序，但每阶段需要可验证结果。接口细节通过样例收敛，不以补齐所有旧方法为完成目标。

## 4. 贯穿阶段的业务样例

1. **正常聊天**：传入或自动创建会话，完成一轮交互，独立编辑消息后继续聊天。
2. **工具循环**：发现并启用工具，审批、执行并继续生成，多模型步骤均有可查询记录。
3. **重生成**：保留原分支或候选，生成新的运行记录，切换后得到正确上下文。
4. **继续生成**：思考回传、临时指令、内容合并、多次用量、工具边界、中止与失败保留。
5. **编辑与显示转换**：内容编辑、提交前处理、显示投影和临时请求转换允许不同；运行提交检测编辑冲突。
6. **导出与恢复**：结构、选择、轮次、贡献和工具结果往返；深历史不依赖递归树序列化。

业务样例采用合成数据和 fake transport，不复制真实角色卡、聊天记录或凭据。真实平台调用另设显式验证入口。

## 5. 当前进度

- 已完成：独立 Message、三种 Session、查询和版本化存储、通用执行记录、SDK-free HTTP Provider（含 Responses）、Generator、独立工具审批与执行、PromptBuilder，以及 Agent 的 chat/run/continue/resume。
- 已验证：正常聊天、工具循环、重生成、续写、显示/保存/请求转换、导出与恢复六组业务样例；新旧测试、TypeScript 构建、浏览器无 Node builtin 构建、无 Buffer 的文本附件处理、包子入口和 legacy 导出。
- 当前验证结果（2026-10-08）：落实 CE 反馈后 npm test 共 241 项，240 通过、1 项真实 API 测试跳过；75 项 3.0 测试全部通过（其中 13 项验证继承与多媒体，16 项验证 CE 接入反馈）。初次重构的 npm pack --dry-run 通过，当前构建、浏览器运行和包导出通过。
- 多媒体补充：Provider 作为可继承公共基类，ChatProvider、ImageProvider、AudioProvider、VideoProvider 分别约束操作；新增 multipart/二进制/GET 任务查询基础设施、视频消息和聊天转换扩展点。内置媒体原生协议尚未实现，具体接入见 [继承与多媒体](./MULTIMEDIA-3.0.md)。
- CE 反馈补充：业务/请求版本分离、会话 metadata、续写提示词与预览一致的构建路径、来源标签变换、合并草稿钩子与工具思考去重、公开平坦存储类型与根顺序、传输 stream/purpose、可配置 thinking，以及 EmbeddingProvider 契约。结果与对接示例见 [反馈落实](./CE-FEEDBACK-3.0.md)。
- 已提供：[3.0 API](./API.md)、[2.x 迁移说明](./MIGRATION-3.0.md)，以及显式 legacy 兼容入口。旧 demo 仍运行 legacy。
- 未执行：真实模型联调、CharacterEditor 代码迁移、跨进程执行现场恢复、npm 发布。此次只在 AgentEngine 工作区实施，业务项目仍使用原版本。
- 当前限制：resume 为本 Agent 实例的接续，不保证工具副作用 exactly-once；数据导入恢复历史事实，不恢复等待审批。PromptBuilder life 按成功构建的模型步骤消费，业务宏副作用在提交 hooks 中结算。手动导入旧历史不推断未知生成用量。
